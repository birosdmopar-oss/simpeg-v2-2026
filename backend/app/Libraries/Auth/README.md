# Modul A — Autentikasi & Akun (Fase 1)

Service/business logic modul ini (`App\Libraries\Auth\*`). Kalkulasi, business rule, dan scoping data (mis. per satker) ditulis di sini — bukan di Controller/Filter (ADR-005).

- `PasswordPolicy` — satu sumber kebijakan password baru (K4, ikut legacy): min 8 karakter, huruf besar, huruf kecil, angka. Dipakai `PasswordVerifier::policyErrors()` untuk ganti/reset password, admin buat/ubah akun, dan password awal `AccountProvisioner`. Frontend mencerminkannya di `features/auth/schemas/password.schema.ts`.
- Identitas akun (DBV-010/CR-013) = `id_pengguna`: claim `sub` JWT, baris `token`, `audit_logs.id_pengguna_actor`, stamp `*_by` master. NIP hanya atribut akun pegawai (`AuthContext::nip()` dari claim `nip`, null untuk akun role 1/3/4/5/8 tanpa NIP). `JwtService::CLAIMS_VERSION` = 2; token format lama ditolak.
- `Role::UL_PEGAWAI` (2/6/7) wajib NIP (`Role::wajibNip()`); aturan akun lain (nama wajib tanpa NIP, NIP angka maks. 18 digit, username ≤ 100, NIP hanya bisa ditautkan) di `UserService`/`AccountProvisioner`.
- `AccountProvisioner` (A-09, dipanggil B-05): NIP pegawai baru yang sudah dipakai sebagai username akun lain (username bebas akun non-pegawai, termasuk akun terhapus) → `ValidationException` 422 `errors.nip` "NIP ini sudah dipakai sebagai username akun lain; ganti username akun tersebut sebelum membuat akun pegawai." — akun tidak dibuat/ditautkan, pemanggil membatalkan pembuatan pegawai (ISSUE-023/CR-019; sebelumnya 1062 → 500). Balapan dua proses untuk NIP yang sama tetap idempoten (`created=false`, akun yang sudah ada). Email pegawai yang sudah dipakai akun lain tidak ikut disimpan (akun dibuat tanpa email, hasil `email_skipped: true` untuk ditindaklanjuti admin; final di B-05).
- Email unik (syarat DBV-010 D-6, CR-019): `PenggunaModel::emailTaken()` membandingkan lewat collation kolom (`utf8mb4_unicode_ci`) di antara akun yang belum dihapus; dipakai `UserService` (buat/ubah akun → 422 `errors.email`, ubah hanya bila email berubah — `hasEmail()`) dan `AccountProvisioner`. Fitur pulihkan akun (A-01 Bagian 8 #6) nanti wajib mengecek ulang email.
- `ResetTokenNotifierInterface` (`App\Interfaces`) — kanal tautan reset password; driver `LogResetTokenNotifier` (development) dan `MockResetTokenNotifier` (test), keduanya ditolak di production. Driver email menyusul (K3).
- Guard konfigurasi production (ISSUE-021, pola notifier di atas): `MockCaptchaVerifier` (`auth.captchaDriver = mock`) dan `auth.exposeResetTokenInResponse = true` (dicek di `ResetPasswordService::request()`) melempar `ConfigException` bila `ENVIRONMENT` = production. Test menyimulasikan production lewat argumen constructor `$environment`.
